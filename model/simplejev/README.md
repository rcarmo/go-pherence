# Simple-JEV-style scoring primitives

`model/simplejev` is a separately authored, model-free MIT component. It accepts ordered, distinct label-token IDs and finite F32 logits, then returns a distribution over only those labels. `Choice` breaks exact logit ties by input order. `Ordinal` uses caller-specified finite values; it does not infer score levels or a Noul scale from a prompt.

`DecodeRequest` admits a separate strict JSON envelope with one state and 1–256 ordered choice/ordinal questions, 2–50 labels each, an explicit 1 MiB body cap, and decoded UTF-8 byte limits on text fields. Object keys must match lowercase field names exactly and cannot repeat; blank/invisible-only text and IDs containing whitespace or controls are rejected. This schema is not the upstream wire format. `Evaluate` accepts an injected provider of ordered label-token logits and returns complete, owned answers only if every row validates; ordinal levels are zero-based label positions. `TokenLogitAdapter` joins an injected renderer, tokenizer and selected-logit backend. It requires an explicit public-ID/model-text pair for every label, verifies that each model-text label adds one distinct token at the actual prompt boundary, and copies mutable tokenizer/provider buffers before scoring. `DecodeTextStateRequest` separately admits a bounded upstream-shaped **text-state subset**: ordered Choice/Score/Noul questions, nullable text instructions and descriptions, and explicit rejection of messages, structured content and media. Its pinned validation fixture comes from upstream Pydantic without running a model. `AssembleTextStateResponse` separately builds public, non-advanced Choice/Score/Noul answers and zero-output-token usage from injected ordered logits; a pinned upstream response fixture checks its bounded output. It rejects raw-logit/advanced mode and malformed provider rows transactionally. `testdata/upstream_prompt_boundary_v1.json` records SHA-256 hashes and lengths for three pinned upstream v1 rendered branches under a byte-tokenizer test double, plus label token IDs and two rejected boundary cases. Its SHA-256 is `f7011071f9690f70cba2eead7ad578009b8267f79ddf5b1f50d50c2cc025012b`; `scripts/simplejev_oracle_prompt_boundary.py` verifies pinned Apache upstream compiler/builder/test-double hashes before generating it. The fixture contains no prompt or chat-template text. The existing `TokenLogitAdapter` checks single-token stability at the actual rendered boundary with an injected renderer/tokenizer. Structural upstream observations do not implement an MIT v1 prompt renderer or qualify a released tokenizer. `CanonicalStructuredState` is an independent, standalone JSON state serializer checked against six synthetic upstream Pydantic/canonical observations in `testdata/upstream_structured_state_v1.json`. It sorts object keys, keeps array order and emits compact readable UTF-8. Its 64 KiB input and 32-level depth limits reject duplicate keys, non-finite or decimal/exponent numbers, integers outside signed 64-bit range, invalid UTF-8 and U+FFFD/U+2028/U+2029; those number and Unicode restrictions are narrower than upstream. It accepts only string/object/array roots and returns owned output. It does not change `DecodeTextStateRequest`, render prompts or validate an upstream structured request envelope. The oracle script `scripts/simplejev_oracle_structured_state.py` pins the Apache upstream request schema and canonical serializer source hashes. This package has no shipped prompt template, concrete model backend or HTTP endpoint. A separate independent upstream fixture checks model-free choice/score probabilities and the nine-bin Noul numerical mapping. It does not qualify upstream request, prompt, tokenizer or model parity, text generation, calibration or model quality. Do not mix its semantics with the existing `model/jevlike` scoring head or reuse the spent Jev bake-off cohorts for selection. The [upstream review](../../docs/validation/simple-jev-upstream-review-20260920.md) records the licensing change and remaining gates.
