# MoJev config, mask and scorer-head boundaries

`ReadConfig` accepts a pinned, metadata-only `MoLeMo-Lab/mojev` PackedScorer config. It validates the 24-layer Qwen3.5-0.8B hybrid text stack (18 linear and six full-attention layers), nested vision metadata, rank-512 readout, 16,384-token context setting, and 64-option `answer` schema. The Qwen3.5 projection shapes come from `loader/config/qwen35_shapes.go`. A successful parse always returns `RuntimeReady=false`.

The repository-owned config fixture is `testdata/mojev_config.json`, from Hugging Face revision `0c8695b6252f4205907433d4e196a94f032e60c3` (5,935 bytes; SHA-256 `1b3fb0dd8ae5a1e334b31bae1cfb2e8212231bd549884819304f29334313f4c9`). The source assessment uses MIT `MoLeMo-Lab/mojev@a74d58cd19ec573e83e8e27f9fecd837b8d830fb`; `mojev/modeling.py` has SHA-256 `a8e93f62d92c6748c5d001fef4f9516d6a74b10158d7265f53bab13f1091d458`. The config fixture contains no tensor payload or inference output. The checkpoint was fetched later for the separate, opt-in scorer-head test described below.

The upstream scorer uses a three-level tree mask: state, isolated questions and isolated candidates. Its encoder runs in BF16 and its two projections and LayerNorm head in F32. The rank-512 readout combines state and question projections with pooled candidate keys, then masks absent options. `TreeMask` supplies a model-free reference for one packed row. `testdata/tree_mask.json` records the pinned upstream allowed matrices for two questions with two candidates and for a padded row with three candidates. The fixture SHA-256 is `200c5864dbf67c941515e195c85a00eb2815ce96cafd34eac93bf340bd5ec57d`; `scripts/mojev_oracle_tree_mask.py` pins the MIT source revision and `modeling.py` hash before invoking `PackedScorer.build_mask`. The upstream isolation and non-empty-row tests passed without model weights (2 passed, 37 deselected). The Go test compares every allowed position and rejects overlapping or malformed spans. Its 4,096-token, 256-question and 64-candidate-per-question limits are reference bounds, not a claim of full 16,384-token checkpoint context support. Empty option spans are allowed; padding rows see only their own diagonal.

`AdditiveTreeMask` composes that reference with a packed-token column mask. `testdata/packed_mask.json` pins two synthetic upstream matrices (SHA-256 `ffa75bba63f5ab1be78bcf14bc907cdccce16971cb26736d52fc8e08fc73faa0`); `scripts/mojev_oracle_packed_mask.py` checks the same source revision and hash. Visible entries are `0`; masked entries have F32 bits `ff7fffff` (`torch.finfo(torch.float32).min`). A diagonal is always visible, even when the packed mask excludes its column. One fixture deliberately claims a padding column in a span to test column filtering; the upstream collator does not produce this inconsistent input. The Go API retains the reference's 4,096-position bound and allocates its own output. After profiling the initial two-mask pass, `TreeMask` and `AdditiveTreeMask` share single-owner validation, then each fills one contiguous, request-owned result. The additive path no longer allocates an intermediate boolean matrix. On an i7-12700 with six visible CPUs, Go 1.26.3, Linux amd64 and `GOMAXPROCS=2`, five 512-position samples (`-benchtime=150ms -count=5`) changed from a median 520,831 to 348,519 ns/op, 1,350,144 to 1,074,432 B/op, and 1,027 to 3 allocs/op. At 1,024 positions the medians were 2,406,322 to 1,234,170 ns/op, 5,321,984 to 4,246,144 B/op, and 2,051 to 3 allocs/op. These benchmarks include validation and owned output; they do not measure inference or peak process memory.

`LoadHead` reads exactly four F32 head tensors from a caller-owned `weights.Source`, checks each shape and returns a copied, transactional `HeadWeights`; closing the source does not invalidate the head. `NewHeadWeights` also accepts and owns supplied F32 tensors. `ScoreHidden` takes already-computed pre-LayerNorm encoder rows and computes the pinned LayerNorm, state/question/candidate pooling, rank-512 projections and masked logits. The approved checkpoint `model.safetensors` was downloaded outside the repository (1,710,234,304 bytes; SHA-256 `eae27bf03e0e44501316cafab2406b1505732ddf4b836d19fbb8deb642f55f50`). `testdata/released_head.json` (SHA-256 `32ae8f212b0a4def89cc2e95f3655ff6612c28cbd0ff5a1398d27f7873b271ff`) pins 12 synthetic token IDs, the upstream BF16 encoder's 12×1,024 pre-norm rows and two fields' F32 logits, with one absent option. The pinned MIT-source probe is `scripts/mojev_oracle_released_head.py` (SHA-256 `dd86f2c5c82fd6169da933c9319529f2e1753d31ea60c716dec4a6f28444792a`). `GO_PHERENCE_MOJEV_CHECKPOINT_DIR=/path/to/verified/checkpoint go test ./model/mojev -run '^TestReleasedMoJevHead$'` verifies the checkpoint hash, calls `LoadHead` and compares native Go logits within 3e-4; the default package test requires no weights. This tests only the head given upstream hidden rows. No tokenizer, native encoder or full Go inference is involved. `BenchmarkMoJevHead` includes input validation, F32 LayerNorm, pooling, projections and owned logits on synthetic 128/512-token inputs. Profiling the initial scalar head put 91.51% of 2.71 seconds of sampled CPU time in projection. The checked SIMD GEMV projection and one-row, request-local LayerNorm scratch preserve released-logit parity. On the i7-12700 with six visible CPUs, Linux amd64, Go 1.26.3 and `GOMAXPROCS=2`, five 128-token samples (`-benchtime=150ms -count=5`) changed from median 21,486,015 to 2,059,313 ns/op, 656,544 to 17,568 B/op and 49 to 11 allocs/op. Five 512-token samples changed from median 22,080,812 to 2,828,795 ns/op, 2,238,624 to 26,784 B/op and 49 to 11 allocs/op. These synthetic numbers exclude encoder execution, checkpoint loading and process memory; they are not end-to-end throughput.

`PackEncodedRows` packs pre-tokenised text state, question prompts and candidate segments into owned, batch-padded token IDs, spans and option masks. `testdata/text_packing.json` (SHA-256 `1a2cb02f7eb9db2fb0b60922e18dc5a8d3224a76465467ca87a465a33b7267a8`) pins a two-row output from upstream `packed_collate`: the first row has a long per-row candidate, the second is padded. `scripts/mojev_oracle_text_packing.py` checks MIT source revision `a74d58cd19ec573e83e8e27f9fecd837b8d830fb` and `mojev/full.py` SHA-256 `5e2972605c190a511cdfb3a1c01358c4855b229c93a1679a6c569c5b43b07b79`; its byte-plus-one tokenizer is a model-free test double. The Go packer caps batches at 16, questions at 256, candidates per question at 64 and row length at 4,096. It requires nonempty encoded segments and at least two candidates per field, as the validated upstream text rows do. It does not validate prompt text, tokenizer IDs or schema semantics.

The checkpoint's `tokenizer.json` (19,989,325 bytes, SHA-256 `06b9509352d2af50381ab2247e083b80d32d5c0aba91c272ca9ff729b6a0e523`) and `tokenizer_config.json` (1,124 bytes, SHA-256 `66e427c470fe580fe8c7b5725d857af23d8417e37fae62667ec698306a19987b`) were fetched outside the repository. `testdata/released_tokenizer.json` pins 18 offline Transformers `Qwen2Tokenizer` text observations, including Unicode, whitespace, digits and special tokens; the opt-in `TestReleasedMoJevTokenizer` verifies both asset hashes and compares `loader/tokenizer.LoadWithConfig` IDs. That fixture has SHA-256 `906157ed4ea409843e51c34fa162b924a7cea8aba927deae5d6f317d80c49818` and was produced by `scripts/mojev_oracle_tokenizer.py` (SHA-256 `626859ba9470fe2c6ac92d6c6b7835fe2337c0fe47a3df8af7e0669c56f6924d`). The fixture does not test prompts, image expansion, or complete tokenizer coverage.

`PackTextRows` renders bounded Choice field prompts, tokenises each text segment through an injected encoder and calls `PackEncodedRows`. An opt-in fixture from pinned MIT `schema.py`/`full.py` and the hash-checked released tokenizer compares two text rows' prompt strings, truncated token IDs, padding, spans and candidate masks. The fixture `testdata/released_packing.json` has SHA-256 `e7501c7c2248d6840fa184b8498e7b5d860c629c6304265a3e8ea74e5b6f6408`; the generator `scripts/mojev_oracle_released_packing.py` has SHA-256 `78adb5f49fd61fc63f6654d3ff2bc1da697d1ba1eeafbb76ee7d8a6bd660f236`. Run `GO_PHERENCE_MOJEV_CHECKPOINT_DIR=/path/to/verified/tokenizer go test ./model/mojev -run '^TestReleasedMoJevTextPacking$'` to check the assets and compare the rows. Other question kinds, full request validation, chat templates and images are not covered.

`AssembleAnswer` handles injected, text-sorted finite logits for Choice, Noul and Score without executing a model. It remaps probabilities to caller order, keeps caller-order ties for Choice and computes Score's expected level. `testdata/public_answers.json` (SHA-256 `c745a9e1f9b573e7caf02a3969bb9b2ef5dc42f7a818cd043762c0dbb7287d76`) pins five synthetic upstream answer cases including ties and extreme logits; `scripts/mojev_oracle_public_answers.py` (SHA-256 `ad1cb546e5e3f15e58869b10cf16aaf0f2b2b120b8fbfe1d5718fc9a9de39ede`) verifies MIT `serve.py`/`full.py` hashes first. The Go API rejects duplicate/empty labels, invalid cardinality and non-finite logits without returning a partial answer. Request parsing, model logits, calibration and HTTP remain separate gates.

Existing Go Qwen3.5 support provides text backbone shapes and state helpers. Neither reference mask is connected to its attention backend; processor/image parity, Go encoder hidden-row parity, end-to-end scoring and service/evaluation are still absent. `RuntimeReady=false`.

A five-sample **cold config parse**, measured on an i7-12700 with six visible CPUs, Go 1.26.3, Linux amd64 and `GOMAXPROCS=2`, yielded 48,138–52,375 ns/op, 18,353–18,356 B/op and 217 allocs/op (`-benchtime=200x -count=5`). An exhaustive allocation profile attributed most bytes to `io.ReadAll` and JSON decoding. Config parsing occurs once per load; no hot-path optimisation was retained or latency improvement claimed. Native Go encoder inference, released end-to-end logits/probabilities, Choice/Noul/Score quality, image input, concurrent admission and service wiring still require separate tests. Checkpoint execution was approved for the bounded head fixture; that approval is not parity evidence for the other paths.
