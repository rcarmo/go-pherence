# MoJev config, mask and scorer-head boundaries

`ReadConfig` accepts a pinned, metadata-only `MoLeMo-Lab/mojev` PackedScorer config. It validates the 24-layer Qwen3.5-0.8B hybrid text stack (18 linear and six full-attention layers), nested vision metadata, rank-512 readout, 16,384-token context setting, and 64-option `answer` schema. The Qwen3.5 projection shapes come from `loader/config/qwen35_shapes.go`. A successful parse always returns `RuntimeReady=false`.

The repository-owned config fixture is `testdata/mojev_config.json`, from Hugging Face revision `0c8695b6252f4205907433d4e196a94f032e60c3` (5,935 bytes; SHA-256 `1b3fb0dd8ae5a1e334b31bae1cfb2e8212231bd549884819304f29334313f4c9`). The source assessment uses MIT `MoLeMo-Lab/mojev@a74d58cd19ec573e83e8e27f9fecd837b8d830fb`; `mojev/modeling.py` has SHA-256 `a8e93f62d92c6748c5d001fef4f9516d6a74b10158d7265f53bab13f1091d458`. The config fixture contains no tensor payload or inference output. The checkpoint was fetched later for the separate, opt-in scorer-head test described below.

The upstream scorer uses a three-level tree mask: state, isolated questions and isolated candidates. Its encoder runs in BF16 and its two projections and LayerNorm head in F32. The rank-512 readout combines state and question projections with pooled candidate keys, then masks absent options. `TreeMask` supplies a model-free reference for one packed row. `testdata/tree_mask.json` records the pinned upstream allowed matrices for two questions with two candidates and for a padded row with three candidates. The fixture SHA-256 is `200c5864dbf67c941515e195c85a00eb2815ce96cafd34eac93bf340bd5ec57d`; `scripts/mojev_oracle_tree_mask.py` pins the MIT source revision and `modeling.py` hash before invoking `PackedScorer.build_mask`. The upstream isolation and non-empty-row tests passed without model weights (2 passed, 37 deselected). The Go test compares every allowed position and rejects overlapping or malformed spans. Its 4,096-token, 256-question and 64-candidate-per-question limits are reference bounds, not a claim of full 16,384-token checkpoint context support. Empty option spans are allowed; padding rows see only their own diagonal.

`AdditiveTreeMask` composes that reference with a packed-token column mask. `testdata/packed_mask.json` pins two synthetic upstream matrices (SHA-256 `ffa75bba63f5ab1be78bcf14bc907cdccce16971cb26736d52fc8e08fc73faa0`); `scripts/mojev_oracle_packed_mask.py` checks the same source revision and hash. Visible entries are `0`; masked entries have F32 bits `ff7fffff` (`torch.finfo(torch.float32).min`). A diagonal is always visible, even when the packed mask excludes its column. One fixture deliberately claims a padding column in a span to test column filtering; the upstream collator does not produce this inconsistent input. The Go API retains the reference's 4,096-position bound and allocates its own output. After profiling the initial two-mask pass, `TreeMask` and `AdditiveTreeMask` share single-owner validation, then each fills one contiguous, request-owned result. The additive path no longer allocates an intermediate boolean matrix. On an i7-12700 with six visible CPUs, Go 1.26.3, Linux amd64 and `GOMAXPROCS=2`, five 512-position samples (`-benchtime=150ms -count=5`) changed from a median 520,831 to 348,519 ns/op, 1,350,144 to 1,074,432 B/op, and 1,027 to 3 allocs/op. At 1,024 positions the medians were 2,406,322 to 1,234,170 ns/op, 5,321,984 to 4,246,144 B/op, and 2,051 to 3 allocs/op. These benchmarks include validation and owned output; they do not measure inference or peak process memory.

`NewHeadWeights` owns and validates four F32 head tensors. `ScoreHidden` takes already-computed pre-LayerNorm encoder rows and computes the pinned LayerNorm, state/question/candidate pooling, rank-512 projections and masked logits. The approved checkpoint `model.safetensors` was downloaded outside the repository (1,710,234,304 bytes; SHA-256 `eae27bf03e0e44501316cafab2406b1505732ddf4b836d19fbb8deb642f55f50`). `testdata/released_head.json` (SHA-256 `32ae8f212b0a4def89cc2e95f3655ff6612c28cbd0ff5a1398d27f7873b271ff`) pins 12 synthetic token IDs, the upstream BF16 encoder's 12×1,024 pre-norm rows and two fields' F32 logits, with one absent option. The pinned MIT-source probe is `scripts/mojev_oracle_released_head.py` (SHA-256 `dd86f2c5c82fd6169da933c9319529f2e1753d31ea60c716dec4a6f28444792a`). `GO_PHERENCE_MOJEV_CHECKPOINT_DIR=/path/to/verified/checkpoint go test ./model/mojev -run '^TestReleasedMoJevHead$'` verifies the checkpoint hash, reads the four head tensors and compares native Go logits within 3e-4; the default package test requires no weights. This tests only the head given upstream hidden rows. No tokenizer, native encoder or full Go inference is involved.

Existing Go Qwen3.5 support provides text backbone shapes and state helpers. Neither reference mask is connected to its attention backend; multimodal packing, released Go encoder hidden-row parity, end-to-end scoring and service/evaluation are still absent. `RuntimeReady=false`.

A five-sample **cold config parse**, measured on an i7-12700 with six visible CPUs, Go 1.26.3, Linux amd64 and `GOMAXPROCS=2`, yielded 48,138–52,375 ns/op, 18,353–18,356 B/op and 217 allocs/op (`-benchtime=200x -count=5`). An exhaustive allocation profile attributed most bytes to `io.ReadAll` and JSON decoding. Config parsing occurs once per load; no hot-path optimisation was retained or latency improvement claimed. Native Go encoder inference, released end-to-end logits/probabilities, Choice/Noul/Score quality, image input, concurrent admission and service wiring still require separate tests. Checkpoint execution was approved for the bounded head fixture; that approval is not parity evidence for the other paths.
