# Pocket TTS local training

`pockettrain` provides read-only Linux preflight and an **experimental SIMD training runner for prepared latent rows**. Default mode stays read-only. Training requires explicit opt-in; sampler numerical/distribution qualification and new-voice quality are unfinished. Separately named Vulkan/PTX attention-backward, flow, transformer and optimiser hybrids are available behind device opt-in. Complete resident GPU training is unfinished.

## Inputs

Supply local paths for the released six-layer English config/model/tokenizer, an aligned JSONL manifest and an explicit recording root. Model and tokenizer SHA-256 pins are required. The command hashes the model body and checks its bounded safetensors header/inventory without decoding tensors.

Syntax-only example; this real-data command has **not** been run:

```sh
go build -o /workspace/tmp/pockettrain ./cmd/audio/pockettrain
/workspace/tmp/pockettrain -mode preflight -backend simd \
  -config /path/english.yaml \
  -model /path/model.safetensors -model-sha256 'REPLACE_WITH_MODEL_SHA256' \
  -tokenizer /path/tokenizer.json -tokenizer-sha256 'REPLACE_WITH_TOKENIZER_SHA256' \
  -manifest /path/aligned.jsonl -source-root /path/recordings \
  -max-rows 1000 -max-audio-samples 840000 \
  -max-text-tokens 512 -max-resident-bytes 6442450944
```

The manifest follows `model/pockettts/training_manifest.go`:

```json
{"path":"speaker/utterance.wav","duration":3.0,"transcript":"a b","words":[{"word":"a","start":0.1,"end":1.0},{"word":"b","start":1.4,"end":2.4}]}
```

Word timestamps are relative to the segment; optional `start` selects the segment offset within the recording. Paths must be local relative paths under `source-root`; `os.Root` rejects symlink escape. A row requires an aligned cut leaving at least one second on each side. The first eligible cut is selected deterministically; no random sampling is implemented.

Recordings must use a canonical 44-byte RIFF/fmt/data header, mono 24 kHz PCM16 or F32. Other valid WAV layouts are deliberately unsupported in this first slice. Input is streamed in bounded chunks; nonfinite, out-of-range and full-scale samples are rejected. The command performs no resampling, downmixing, clipping or file writes.

## Sample and resource limits

Timestamps round to the nearest 24 kHz sample. Codec geometry uses `ceil(samples/1920)` as Mimi's encoder does. The existing training envelope permits 62 prompt frames and 375 target frames. A full 5-second prompt needs 63 frames and is rejected; it is not silently trimmed. The maximum whole recording defaults to 35 seconds, independent of per-row prompt/target limits.

File/row/header/text/token ceilings are checked before relevant allocations. Config/tokenizer/model-header limits are 1 MiB each. The explicit model-file ceiling is at most 16 GiB, manifest ceiling at most 64 MiB, row ceiling at most 100,000, line limit 64 KiB, path/transcript limit 4,096 bytes, word limit 512 and word-byte limit 128. Tensor headers require unique keys, BF16/F32 types, integer shapes, exactly two offsets and complete, contiguous, non-overlapping payload coverage; null/nonnumeric geometry is rejected. Pins must be lowercase SHA-256. Unsupported `-backend vulkan` or `-backend ptx` fails before file access. The default preflight handler still rejects non-preflight modes; the separate `train` mode below opts into updates. Full-device training is not wired; the separately named training hybrids below have narrower scopes.

JSON output includes input digests, admitted rows, sample indices, exact frame/token/sequence counts and estimated training resident bytes. `training_command_implemented` and `model_tensor_values_validated` are false. The resident estimate excludes checkpoint save/load peaks, free-disk admission and actual execution/quality. Model tensor values are hashed but not scanned for finiteness. Model-state resume is separate from reproducible dataset/RNG resume.

## Experimental prepared-row training

`-mode=prepare` turns admitted aligned recordings into version1 prepared JSON using frozen Mimi on SIMD. It records model/config/tokenizer/manifest pins and a versioned cut/normalisation/EOS-padding policy. Targets are normalised using the initial model's latent mean/std; voice latents remain raw.

```sh
GO_PHERENCE_DISABLE_NVIDIA=1 GO_PHERENCE_DISABLE_VULKAN=1 \
  go run ./cmd/audio/pockettrain -mode=prepare -backend=simd \
  -config=/path/english.yaml -model=/path/model.safetensors \
  -model-sha256=<model-pin> -tokenizer=/path/tokenizer.json \
  -tokenizer-sha256=<tokenizer-pin> -manifest=/path/aligned.jsonl \
  -source-root=/path/recordings -prepared-output=/new/path/prepared.json
```

Preparation selects the first eligible cut, encodes prompt/target separately and appends one zero target row as the explicit EOS boundary. Because this row counts against the375-frame envelope, target codec output must be≤374frames. This is a restricted deterministic native preparation policy, not all upstream random augmentation/cut semantics. No resampling/clipping occurs. Preserve source recordings and preparation provenance.

### Experimental device hybrids

`ptx-attention-hybrid` and `vulkan-attention-hybrid` offload causal attention backward. Model forward, other derivatives, minimal-LSD time-JVP, clipping, AdamW/EMA and checkpointing run on CPU.

`ptx-flow-hybrid` and `vulkan-flow-hybrid` offload flow-head linear/activation/normalisation/modulation forward, time-JVP and reverse-over-forward derivatives. Sinusoidal time embeddings and their scalar adjoints, transformer/FlowLM work, the weighting MLP, loss reductions, clipping and AdamW/EMA run on CPU. The minimal-LSD endpoint returns only its input VJP upstream; its direct parameter, conditioning and time gradients are discarded. The runner admits only one named device scope per run.

`ptx-transformer-hybrid` and `vulkan-transformer-hybrid` offload the complete stateless transformer: projections, affine norms, RoPE, exact-key causal attention, GELU-tanh MLP, residuals/layer scales and input/parameter gradients. Sequence assembly, conditioner/EOS/flow losses, clipping and AdamW/EMA run on CPU. The transformer executes twice per update: first with zero seeds to produce conditioning, then again with the loss seed. Parameters must remain immutable between those calls; no update occurs between them. This scope keeps the optimiser on CPU; full-device training is unfinished.

`ptx-optimizer-hybrid` and `vulkan-optimizer-hybrid` keep forward/loss/backward on CPU and offload gradient accumulation, chunk norm summaries and AdamW/EMA to resident buffers. The global norm combines small summaries on CPU. A full coherent parameter/moment/EMA snapshot returns to the host each update, so CPU training and existing checkpoints use current values. Resident state is initialised lazily after restore; buffers persist across updates. The byte ceiling applies to resident logical storage in this mode. Host mutation after synchronisation invalidates updates/checkpoints; uncertain native failure blocks retry and publication.

`ptx-resident-hybrid` and `vulkan-resident-hybrid` combine flow/transformer tape execution with resident optimiser state under one owner. Current parameter buffers are bound read-only without another device upload; selected parameter gradients accumulate directly on device. Endpoint/forward tapes do not accumulate parameters. Conditioner, EOS, weighting, sequence assembly, time embeddings/scalar adjoints, loss interpolation/reductions and the final global norm reduction stay on CPU. Updated full state returns to the host each completed update for CPU components and coherent checkpoints. Residency does not imply a full-device trainer or a speedup.

`ptx-resident-weight-hybrid` and `vulkan-resident-weight-hybrid` extend the resident scope with the learned affine/ReLU weighting MLP, including bias/weight and time-input gradients. Only the loss-seeded backward accumulates weighting parameter gradients; forward returns log-variance values without accumulation. Scalar losses stay on CPU. These modes have distinct v1 replay identities; resident-v1 keeps CPU weighting and cannot resume under the weighting scope.

`ptx-resident-projection-hybrid` and `vulkan-resident-projection-hybrid` also execute the speaker/audio projections and EOS affine head on resident tapes. Their parameter gradients stay on device; returned input gradients feed shifted-audio/BOS and voice differentiation. Empty voice conditioning explicitly produces a zero speaker-weight gradient. Token embedding lookup/accumulation and sequence assembly still run on CPU. These modes use `*-resident-projection-hybrid-v1`, distinct from resident/weighting v1.

`ptx-resident-sequence-hybrid` and `vulkan-resident-sequence-hybrid` additionally execute token embedding lookup/VJP, prefix assembly and shifted BOS/audio assembly on device tapes. Repeated-token embedding gradients sum in row order without atomics. Embedding/BOS gradients stay device-side, including explicit zero gradients for empty text/voice boundaries. These modes use `*-resident-sequence-hybrid-v1`; existing scopes retain CPU sequence arithmetic. Boundaries still transfer between tapes, scalar losses/time embeddings and the final norm-summary reduction stay CPU, and coherent host state still synchronises each update. This is not full-device training.

`ptx-resident-time-hybrid` and `vulkan-resident-time-hybrid` also compute sinusoidal time values/JVPs and reverse-over-forward time adjoints inside flow tapes. They use native F32 trigonometry rather than host F64-rounded sin/cos; the new scopes are `*-resident-time-hybrid-v1`. Frequencies must be finite and angles bounded to `abs(time*frequency)<=8192`.
