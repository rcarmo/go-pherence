# Needle 3 packed-only archive prerequisite

The current Needle 3 archive path retains decoded F32 tensors and separate immutable CQ matrices. `Options{Packed:true}` uses those matrices for selected projections, but it is a hybrid path, not packed-only inference. The tiny upstream-derived `.cact` fixture now has a coverage regression test in `model/needle/packed_coverage_test.go`.

`TestPackedArchiveCoverage` loads `loader/needle/testdata/needle3.cact`, checks every packed matrix against the corresponding decoded tensor shape, then performs a cached packed decoder step. This fixture has **69 decoded tensor names** and **30 packed matrices**. Decoded storage is **25,012 bytes**; **15,104 bytes** correspond to packed-covered tensors or layer slices, while **9,908 bytes** remain dense-only. Packed matrices retain another **156,864 bytes** in this small fixture, including CQ payloads, owned codebooks and 2-/4-bit lookup tables. These are logical payload counts, not process RSS or transient peak. Tiny lookup-table overhead makes this fixture unsuitable for extrapolating production memory savings.

The executable blockers are explicit: `newModel` requires every expected decoded tensor and verifies finite values; `execution.param` and `NewDecoder` prepare views by decoded tensor name; the trunk gathers token embeddings from decoded storage even when `Packed` is set; `SliceDepth` clones decoded tensors before remapping packed matrices; `Checkpoint()` serializes decoded tensors. Releasing decoded CQ storage without addressing these consumers would make the archive incomplete. Dense-only norms, gating, head and control tensors still need ordinary storage. The loader also currently materializes and validates each archive record as F32 before building the model.

A packed-only design needs a separate admitted representation and shape metadata, packed embedding-row access, decoder parameter preparation that skips packed-covered leaves, explicit policy for depth slicing/checkpoint export, and a bounded load/validation budget that accounts for decoded scratch and CQ storage without simultaneously retaining both. It must preserve the current decoded default and reject unsupported CQ/KV formats. Independent full/cached/head parity, source-archive ownership, cancellation, concurrency, process RSS and released-size performance on each architecture are separate gates. This test does not enable packed-only loading, improve throughput, or grant production admission.
