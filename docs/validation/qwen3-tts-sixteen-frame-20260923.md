# Qwen3-TTS sixteen-frame capped greedy parity

The approved pinned 0.6B CustomVoice checkpoint yields sixteen greedy frames for Ryan/English `Hello world` without sampling codec EOS. Native Go and Rust/Candle agree on all sixteen semantic IDs `[1995,215,212,1181,462,251,530,122,1792,1792,1086,1086,1086,1724,1724,1792]` and all 240 acoustic IDs. The 24 kHz mono waveform has 30,720 F32 samples (1.28 s); maximum absolute Go/Rust difference is `1.1809170246124268e-6`, mean absolute difference `6.532373331517386e-8`. The independent sixteen-frame gate uses its own `1.3e-6` limit; the eight-frame gate remains `1e-6`. No production TTS, naturally observed EOS stop, stochastic sampling, intelligibility or arbitrary-length behaviour follows from a run that fills its cap.

The fixture uses model revision `85e237c12c027371202489a0ec509ded67b5e4b5` and Rust/Candle checkout `TrevorS/qwen3-tts-rs@711ceee07cad92673f86de8997bdf54c30caa49f`. `reference.json` records the model/tokenizer hashes and the sixteen-frame oracle source, code and waveform SHA-256 values. Copy `scripts/qwen3tts_oracle_sixteen_frames.rs` to that checkout's `examples/oracle_sixteen_frames.rs`, then run `cargo run --release --example oracle_sixteen_frames --no-default-features --features cpu -- <pinned-model-dir> <output-dir>`. The code now calculates causal left-padding once per output time rather than testing every tap for every input channel. It keeps the same input-channel and tap accumulation order, and the existing deterministic scalar differential test passes bit-for-bit across dense/depthwise, dilated and padded cases. Released first-, four-, eight- and sixteen-frame waveform gates passed without changing any tolerance. The sixteen-frame opt-in race test and model-free whole-tree race suite also passed after the edit.

## Minimum-token EOS policy

The pinned Rust library's `generate_codes` path applies repetition penalty, the codec reserved-token mask, then suppresses EOS while `token_count < min_new_tokens` (default 2). Its separate standalone `generate_audio` loop sets `min_new_tokens: 2` but samples without that suppression; `--compare` also disables EOS stopping. Go keeps `GenerateCappedGreedyCPU` unchanged for the original greedy oracle and adds a separately named `GenerateCappedGreedyMinTwoCPU` for the library's minimum-two-token policy. It still samples greedily and caps at sixteen frames. Synthetic tests force EOS to be highest from prefill, confirm two complete frames before stopping, reject EOS as an acoustic frame, and check a one-frame cap. The reserved-token selector rejects nonfinite unsuppressed logits and an all-suppressed candidate set. The pinned eight-/sixteen-frame and fixed four-frame released tests retain exact codes and numerical thresholds. Synthetic policy tests passed ten times under race; the model-free whole-tree CPU race, vet, build and Linux arm64/riscv64 cross-builds passed. Neither the released prompt nor this synthetic policy fixture demonstrates natural EOS on real text, and no seeded top-k/top-p stochastic parity is claimed.

## Pinned CPU sampling probe

A small independent Rust/Candle CPU probe from checkout `711ceee07cad92673f86de8997bdf54c30caa49f` now records six seeded choices for each of top-k ties, top-p ordering, temperature-zero greedy and sign-aware repetition adjustment, plus reserved-token suppression. The generator `scripts/qwen3tts_oracle_sampling_probe.rs`, JSON under `model/qwen3tts/testdata/customvoice_0b6_ryan_hello/`, and SHA-256 values in `reference.json` are checked by a default offline Go test. It uses synthetic five-logit rows, not released model logits; no checkpoint is loaded. The pinned CPU top-p comparator orders token indices by their logits (`row[b]` and `row[a]` in the sort closure; these are token indexes, not the outer batch index). CPU top-k keeps ties at the threshold, CPU top-p keeps the first cumulative probability strictly greater than `p`, and multinomial sampling walks the filtered logits in original token-ID order using a PCG `f32` draw. The generic Go `runtime/sampling` sampler truncates top-k ties, uses `>=` for top-p and draws in sorted-candidate order. A direct comparison with the pinned synthetic probe produced different selections on the top-k-tie and top-p rows even when supplied the same PCG draws. Do not substitute the generic sampler and declare Rust distribution or sequence parity. A separate native `ReferenceCPUSampler` now matches all token sequences in the synthetic probe and the released-prefill single-step fixture, including the controlled near-tie rows. It keeps the pinned CPU PCG `f32` draw, top-k ties, strict top-p cutoff, original-ID multinomial walk, sign-aware repetition adjustment and reserved-control/EOS filtering without changing `runtime/sampling`. Input and configuration validation, caller-logit preservation, per-sampler state isolation and independent concurrent samplers passed ten race-instrumented repetitions; the model-free whole-tree CPU race, vet, build and arm64/riscv64 package cross-builds passed. It has not been wired into autoregressive synthesis. Default sampling over multiple real Talker continuations still needs a pinned released-model seeded oracle and explicit output/quality qualification before it can be enabled.
