# Needle 2 source CQ/A8 reference -- 2026-09-20

Needle 2 source checkpoints now support CQ-W4/A8 inference and STE training with FP32 KV, including cached decoding, full-trunk AdamW and LoRA updates. The new CLI name is `needle2-cq4-a8-fp32kv`. It is deliberately different from Needle 3's `needle3-cq4-a8-kv8`.

## Two generation-specific differences

Pinned upstream `741ee892c5f8c4f5c0bb467c9566ea7a1eba919b` uses the same group-128 CQ weight preparation, but `configure_deploy(kv_bits=8)` sets `KV_BITS=0`: the simulated KV tensors remain full precision. Its lower-bit KV modes use a different CQ operation and are not implemented here. The Go API therefore requires `KVBits: 0` for Needle 2 and rejects nonzero values rather than silently changing their meaning.

Needle 2 also leaves the normalized, RoPE-applied query in FP32; Needle 3 applies query activation quantization there. The previously shared query path produced 57 mismatched CQ logit elements in the new fixture, and a separate activation-only check also failed. Forward and cached attention now apply that query quantization only to Needle 3. This did not change FP32 inference, but matters when A8 is enabled.

Weight preparation uses the same [pre-scaled Hadamard reference](needle-engram-width-20260920.md) introduced for Needle 3 source CQ. This remains a dequantized reference/training path, not packed execution or a Needle 2 archive reader.

## Usage

```go
opts := needle.Options{Quant: &needle.Quantization{
    WeightBits: 4, ActivationBits: 8, KVBits: 0,
}}
```

Use those options with `Forward`, `LossGrad`, `TrainStep`, adapter training or `DecoderOptions.Execution`. The new mode has the existing work/cache/context bounds and immutable model ownership.

```sh
bin/needle -model checkpoints/needle2-source.safetensors -input tokens.json \
  -numerics needle2-cq4-a8-fp32kv -max-new 8
bin/needle -model checkpoints/needle2-source.safetensors -input tokens.json \
  -mode train -numerics needle2-cq4-a8-fp32kv -steps 10 -lr 0.001 \
  -out checkpoints/needle2-source-trained.safetensors
```

CLI numerics names must match the checkpoint generation. Needle 2 auxiliary heads remain FP32-only and explicitly reject quantized inference/training. Head quantization, low-bit CQ KV, deployed Needle 2 archives, MTP objectives and mixed-bit recipes are not qualified by this work. Confidence calibration is unchanged.

## Reference and tests

[`scripts/needle2-reference.py`](../../scripts/needle2-reference.py) now accepts `--quantized`. It extracts architecture and quantization files from the exact Git pin, checks CPU JAX, configures upstream deployment numerics and emits logits/loss/all gradients, CQ-prepared tensors and activation-only logits. FP32 generation remains the default.

```sh
PYTHONDONTWRITEBYTECODE=1 JAX_PLATFORMS=cpu CUDA_VISIBLE_DEVICES='' \
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /path/to/cpu-jax-venv/bin/python scripts/needle2-reference.py \
  --upstream /path/to/needle --quantized \
  --output model/needle/testdata/needle2-cq.json
```

The fixture contains 29 trunk tensors; upstream loss is `2.759763240814209`. Tests pass at the existing CQ tolerances: logits `3e-5` absolute / `1e-3` relative, loss `2e-6`, gradients `4e-5` / `3e-3`. Independent checks cover prepared weights, inference using upstream-dequantized weights and A8-only inference. No tolerance was widened.

Per-prefix cached/full recomputation matches, and eight greedy output IDs agree exactly between cached and uncached generation. Full-trunk and twelve-step LoRA updates reduce the tiny fixture loss without changing the original model. CLI tests train, save/reload and generate, and reject a generation-mismatched numerics name. This is fixture-level numerical evidence, not released Needle 2 quality, accuracy or throughput measurement.
