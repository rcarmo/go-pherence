# Whisper native FP16 projection diagnostic — 1 October 2026

The two tested FP16 projection variants are slower than the existing F32 tile64 kernel on Sigma. Both variants passed six synthetic shapes. All experimental backend changes were reverted; no model, service or default uses FP16 from this experiment.

## Scope and result

The experiment started at `bacd9dc94ea7eb1b29f332097a543ea1e3e12cbc`. It explicitly queried and enabled Vulkan 1.2 `shaderFloat16`, while leaving `shaderInt8` and 16-bit buffer storage disabled. Packed weights used core `uint32` storage. Two 2048-element shared arrays used F16; multiplication, accumulation, bias and output used F32. The tile was 64×64 with K32 and a 16×16 workgroup.

The test rounded both arms' synthetic activations to F16 before upload. Candidate weights were packed as F16; baseline weights were their decoded F32 values. Exact output agreement therefore covers the same rounded inputs and reduction order. It does not qualify the precision change against unrounded Whisper activations. No trained model, VAD, flash-attention or end-to-end request ran in this window.

Each large shape had a warm-up and six measured samples per arm, in three alternating ABBA/BAAB blocks within one process. Times include host dispatch and fence completion; creation, upload and download are excluded. These are warm kernel diagnostics, not six independent processes or whole-request timings.

Both variants also passed 1/1/1, 2/3/5 and 33/65/63. All outputs matched the rounded-input F32 kernel bitwise. Small shapes passed the existing independent CPU reference at absolute/relative tolerance `2e-5`, unchanged. Sentinel and native-memory cleanup checks passed. The rejection is based on measured latency; shared-storage reduction alone did not improve these kernels. Other FP16 arithmetic, vectorisation and cooperative-matrix designs were not evaluated.

## Admission failures and correction

The first module failed before dispatch with `unsupported or malformed Vulkan shader contract: opcode/word framing`. The rejected instruction was `OpSourceExtension` (opcode 4), a compiler debug record. `spirv-opt --strip-debug` removed it. The runtime opcode envelope was not widened to admit that record.

The first bitcast prototype used dynamic vector indexing and hit the same error for `OpVectorExtractDynamic` (opcode 77). The final shader uses fixed `.x`/`.y` components, retaining the existing instruction envelope. The dynamic prototype was replaced; its failure log is retained. Its module can be regenerated by replacing the fixed-component selection in the retained source with `unpackFloat2x16(weight[i>>1])[i&1]`.

Both final modules passed `spirv-val --target-env vulkan1.2`. The temporary FP16 admission added only explicit Float16 types/capability and scalar F16/F32 conversion, with descriptor and push layouts restricted to 32-bit scalars. Baseline admission still rejected FP16. Offline Vulkan tests and vet passed before native execution. The patch includes feature-query ABI, requested-bit, unsupported-device, missing-symbol, device-failure and baseline-upgrade rejection tests. Optional-chain rollback and full-tree/cross-platform qualification of that patch were not completed; the patch is retained only as rejected experimental evidence.

An independent read-only review timed out after 120 seconds. No independent review approval is established.
