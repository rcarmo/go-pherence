# Decider v1.5 Noul question fallback

`NoulQuestionV15` renders an optional-instructions Noul question as a separately named, model-free helper. The existing pinned Go `renderQuestion` and `Runtime.SystemOne` still reject a question without instructions. No service route, model execution, or checkpoint changed.

Current Apache-2.0 upstream `Mapika/decider` at `a5120cce45b9ff70964fac54ea6e8c1ac5b08c7f` renders an instructionless Noul question as `Which answer fits the context?` only when a `true` or `false` criterion has a description. The options remain ordered `no` and `yes`, with supplied descriptions appended. Four frozen observations were reproduced from `decider/systemone.py` (SHA-256 `884e4b0bae36f5e09dbd689b4390e94320cbbd77f7b8d675e50490b1d7c61d34`): true-only, false-only, both descriptions and explicit instructions. The Go helper accepts one or both named criteria, rejects duplicates, unknown names and missing descriptions when instructions are absent, returns an owned option slice, and can feed the existing `BuildPrompt` explicitly. An instruction-bearing question renders like the pinned Go path.

Upstream Python also accepts `bool` as an alias and JSON object criterion maps. The Go helper accepts its existing typed `Question{Type:Noul, Criteria:[]Criterion}` representation; it does not add a JSON request parser or duplicate the upstream server. It preserves the pinned rejection for instructionless Noul in `SystemOne` until a caller deliberately chooses a versioned request path. Synthetic fixture and hostile-input tests passed ordinary and ten race repetitions. This check does not imply model quality, calibration or released-checkpoint parity for the new prompt.
