# Issues #3–#11 validation, 2026-09-19

The pathname audit remains enforced by Go, Make and no-checkpoint GitHub checks.
The follow-on fixes resolve the failures recorded by that audit; issue #2
(frozen-scorer training) was deliberately left untouched.

| Issue | Resolution |
|---|---|
| #3 | Pad the empty GGUF fixture to the default 32-byte data alignment, then assert the actual missing router-tensor error. Loader validation is unchanged. |
| #4 | Honour any nonempty NVIDIA-disable value before discovery or lazy CUDA init. A subprocess regression proves `nvidia-smi` is not invoked; the enabled CUDA parity test still requires real execution. |
| #5 | Dense batch GEMM and singleton GEMV have different FMA/reduction orders. The local parity assertion now has a bounded tolerance, rejects nonfinite values and tests both paths against float64 reductions. Shared exact comparisons and quantised trajectory contracts remain unchanged. |
| #6 | Use the supported Qwen3.5 tensor names and checkpoint convolution layout in the shared fixture and streamed-prefill fixture consumer. No speculative loader aliases were added. |
| #7 | Test raw-contiguous and grouped/head-expanded QKV helpers separately, including ordering, one-to-one heads and malformed dimensions/lengths. |
| #8 | Marshal CUDA JIT options as pointer-sized slots with a real Go buffer pointer and a by-value integer size. Keep the buffer alive through the foreign call; no fabricated pointer or vet suppression. |
| #9 | Extract the SIMD result to a register and store exactly four bytes into the Go int32 return slot. Native assembly remains enabled; signed/zero/extreme coefficient tests match the scalar contract. |
| #10 | Keep Linux/amd64 startup code in its platform file and provide clear unsupported-platform startup and Community-1 interfaces elsewhere. Foreign binaries compile without pretending to implement Community-1 execution. |
| #11 | Observe asynchronous quarantine state through the mutex-protected `Status()` API, and release the test-only hold during cleanup. Runtime quarantine/resource-retention semantics are unchanged. |

The GPU-enabled full run exposed one more test-setup issue: the Whisper
word-timing constructor test reached CPU-backend policy validation before its
intended missing-generation-metadata assertion. It now sets the required CPU
policy explicitly, as the neighbouring constructor tests already do.

## Verified on this host

Environment: Go 1.26.3, Linux/amd64, RTX 3060 12 GiB.

* `make host-check` passes: layout/default checks, `go build ./...`, `go vet ./...`
  and whole-tree tests with NVIDIA disabled.
* With NVIDIA enabled and GPU memory available, `go test -p=1 ./... -count=1
  -timeout=120s` passes. Serial packages avoid competing CUDA contexts during
  validation. All backend tests also pass with NVIDIA enabled.
* `GO_PHERENCE_TEST_CUDA_JIT=1 go test ./backends/nvidia/runtime -run '^TestJIT'
  -count=1 -v` verifies valid PTX loading and invalid-PTX error-log writes on the
  device. The host ABI check also passes with `-gcflags=all=-d=checkptr=2`.
* Gemma4 MTP post-attention RMSNorm passes real GPU/SIMD parity. Its disabled-path
  subprocess regression passes without GPU discovery.
* `go test ./model ./model/qwen` passes natively and with `GODEBUG=cpu.all=off`.
  Q6 integer-dot/scalar parity and signed return tests pass.
* Race checks pass for `runtime/speechjob/...`, `cmd/audio/speechjobserve` and
  `model/qwen`; fatal-drain quarantine passes 30 repeated race runs.
* `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build ./...` and the equivalent
  RISC-V build pass. Speech-job runtime/command test binaries compile for both
  architectures but were not executed. Cross-builds do not validate hardware.

The user authorised stopping GPU services. Only `llama-qwen38-gsq.service` was
stopped, freeing about 11.6 GiB; InvokeAI and ComfyUI were left alone. The service
was restarted afterwards, returned to `active/running`, and its `/health`
endpoint returned `{"status":"ok"}`. No checkpoint assets or service definitions
were changed.

These passes cover the tests runnable with this host's assets and gates. They do
not establish missing full-model reference parity, native ARM64/RISC-V execution,
or the out-of-scope experiment in issue #2. Older audit pages retain their dated
failure reports as history.
