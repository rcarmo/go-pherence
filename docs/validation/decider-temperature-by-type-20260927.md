# Decider optional per-answer-type temperatures

The native 0.8B Decider state-first scorer now accepts optional `temperature_by_type` values for `choice`, `noul` and `score`. An absent entry falls back to the existing scalar `temperature`; the pinned release config has no map, so its default probabilities and released logits path are unchanged. Every isolated Score level row uses the Score temperature.

The model-free behaviour follows the Apache-2.0 upstream `Mapika/decider` source at `a5120cce45b9ff70964fac54ea6e8c1ac5b08c7f` (`decider-ai` v1.5.0), specifically its v1.4 `decider/temperature.py` state-first resolution and `tests/test_temperature.py`. The Go model loader still pins the older source `c4daaac28af9fea95d627015cffa2dd5a5926ee6` and released 0.8B model revision `1ea54127d3bd52f6d753d9257b32a6380b873907`. This addition does not change model weights, prompt construction, label logits or inference architecture.

For example, a config with `"temperature":1.03` and `"temperature_by_type":{"noul":2.22,"score":1.38}` uses 1.03 for Choice, 2.22 for Noul, and 1.38 for each isolated or listwise Score row. Unknown keys (including `bool` and `scale`), nonnumeric values, zero, negatives, NaN and infinities are rejected. Missing or empty maps preserve the scalar path. `SystemOne` uses the owning question's type when scoring each planned row; no schema-first cache exists in this Go port, so upstream schema-first temperatures, request overrides and `/health` reporting are outside this slice.

Synthetic tests verify map validation, scalar fallback, Score row ownership and numerical probabilities against an independent logistic calculation. A tiny fixture verifies config loading and rejection. The already pinned released token/logit fixture remains separate: no released checkpoint or new calibration cohort was executed for this addition. A temperature fitted to labelled data would need its own held-out calibration and quality evaluation before adoption.
