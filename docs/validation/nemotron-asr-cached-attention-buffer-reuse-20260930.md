# Nemotron ASR cached-attention output-buffer reuse — 30 September 2026

`Encoder0Attention.ForwardCachedChunk` now reuses its owned K projection as the output GEMM destination after `Encoder0KVCache.Update` has copied K into independently owned visible/cache storage and attention scoring has consumed the visible K. The destination is cleared before accumulation. The returned output remains independent of caller input, previous outputs, cache and model weights; rejected outputs still leave the caller cache uncommitted. No tolerance, GPU path or fallback policy changed.

Baseline: clean `9fa6984ab192fe864cc946d63eefd094a29512a0`, Go 1.26.3, Linux amd64, Intel i7-12700, `GOMAXPROCS=4`, released ASR checkpoint SHA-256 `9eebdd6590289cb3030f310858f3df93256600a800a3e8200c5993d5f967e174`. With checkpoint and JFK WAV loading outside the timer, five five-iteration `BenchmarkPCMGenerationStreamJFK` samples before change took 6.37–6.88 seconds per 11-second request, with 1,319,737,075–1,319,737,097 B/op and 25,596 allocs/op. Five corresponding samples after change took 6.24–6.61 seconds, with 1,305,974,515 B/op and 24,756 allocs/op. The change saves about **13.76 MB and 840 allocations per request** in the matched steady five-iteration benchmark. Timing distributions overlap, so this is not a proven full-request speedup. Both measured requests remain faster than audio duration on this host.

The independently labelled AMI ES2004a 530–630-second excerpt was also run three times through a CPU-only compiled CLI after this change. Process-wall times including WAV and checkpoint load were 57.31, 57.64 and 58.62 seconds, against earlier 58.40–60.22-second SIMD runs. All decoded transcripts agreed with the saved first-run text on this run. The ranges overlap; the file hashes identify saved outputs but are not a generated-output acceptance gate. The 100-second JFK pinned PyTorch reference run passed: 1,663 decisions, 411 nonblank, zero decision mismatches; PCM input and tower stage distributions had zero values outside their original thresholds.

Checks passed:

- Released cached-attention and composed-block parity across lookahead 0/3, including mask, relative-position and output checks against independent PyTorch fixtures. Existing absolute/relative thresholds were unchanged.
- Rejected-output transactional cache test; new successive-call output ownership test with a zero-weight synthetic model.
- 100-second JFK PCM generation reference comparison; package and CLI tests; focused `-race` tests; affected `go vet`; `go build ./...`; Linux ARM64 and RISC-V test-binary cross-builds. Cross-builds do not assert native speed or execution.

Normal timing and allocation runs were separate from the `-memprofilerate=1` attribution runs. The latter still identify K/V cache copying as a larger allocation hotspot; in one attribution run `Encoder0KVCache.Update` directly allocated about 614 MB, including visible and retained copies. Loader allocation in the attribution profile is outside benchmark timing. Further optimisation must preserve cache ownership, cancellation and rollback. Evidence is local under `/workspace/tmp/nemotron-ami-es2004a-530-630/asr-cache-reuse-*` and `/workspace/tmp/nemotron-ami-es2004a-350-410/asr-warm-5x5.txt`; no model/media/profile binaries are committed.

The host NVIDIA GPU remains unavailable after the separate [Vulkan Xid79 event](../../benchmarks/speech-foundations/ami-pilot-contract-20260913/nemotron-530-630-followup-20260930.md). No PTX, Vulkan, CUDA, reset or recovery workload was run for this change. GPU stability, long-lived service throughput, wider labelled quality and other hardware are still open.
