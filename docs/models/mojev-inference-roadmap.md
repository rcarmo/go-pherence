# MoJev inference roadmap

The native MoJev slices validate pinned metadata, synthetic tree/packed masks and a separate F32 scorer head against released weights. `model/mojev` accepts a 5,935-byte config fixture from [`MoLeMo-Lab/mojev`](https://huggingface.co/MoLeMo-Lab/mojev) at revision `0c8695b6252f4205907433d4e196a94f032e60c3` (MIT; SHA-256 `1b3fb0dd8ae5a1e334b31bae1cfb2e8212231bd549884819304f29334313f4c9`). After explicit approval, the 1,710,234,304-byte `model.safetensors` was fetched outside the repository and checked against SHA-256 `eae27bf03e0e44501316cafab2406b1505732ddf4b836d19fbb8deb642f55f50`. The independently inspected [MIT source](https://github.com/MoLeMo-Lab/mojev) is pinned at `a74d58cd19ec573e83e8e27f9fecd837b8d830fb`; `mojev/modeling.py` hashes to `a8e93f62d92c6748c5d001fef4f9516d6a74b10158d7265f53bab13f1091d458`.

The checkpoint declares `PackedScorer`: a Qwen3.5-0.8B encoder with 24 text layers (three linear attention followed by one full attention, repeated six times), width 1,024, BF16 encoder weights, a rank-512 F32 projection and LayerNorm head, and a nested Qwen3.5 vision config. The saved schema declares one `answer` choice field with 64 slots. The source builds a three-level additive attention tree intended to isolate sibling questions and candidates; candidate scores combine pooled state/question query and candidate key and mask absent options. A same-position released-model probe found that changing the second candidate of question A changed both logits of question B by about 0.21 and 0.18, despite the 4D tree mask disallowing that edge. Changing question B's prompt left question A's logits unchanged. This is a reproducible counterexample to model-level sibling isolation for the pinned Transformers 5.17.0 CPU path, not evidence of Go encoder behaviour. Layer hooks localise the first cross-question hidden-row change to layer 0 (linear attention), before the first full-attention block at layer 3. See [`released-isolation-20260924.md`](../validation/mojev-released-isolation-20260924.md). Existing `loader/config/qwen35_shapes.go` admits the text projection geometry. `model/mojev.TreeMask` checks a separate, model-free single-row allowed-position matrix against two pinned upstream cases, including a padded row. `model/mojev.AdditiveTreeMask` also applies a synthetic packed-token column filter and retains the diagonal with the upstream F32 mask floor. Both single-row references are bounded at 4,096 positions, 256 questions and 64 candidates per question. Neither mask is connected to attention. The independent `model/mojev.LoadHead` reads four F32 tensors from a caller-owned source; `ScoreHidden` consumes pre-LayerNorm rows, owns its weights, and matches the approved checkpoint's readout for one 12-token/two-question text probe within 3e-4; see [`model/mojev/README.md`](../../model/mojev/README.md). `model/mojev.PackEncodedRows` separately matches a model-free two-row text collator fixture for supplied token IDs and spans. Eighteen bounded released text-tokenizer observations match Go `loader/tokenizer.LoadWithConfig` with both assets hash-checked. A separate two-row Choice prompt/packing fixture matches rendered prompt text, truncated IDs, padding and spans through `model/mojev.PackTextRows`. `model/mojev.DecodeTextRequest` adds bounded text-state request parsing for Choice/Noul/Score with ordered candidate keys and explicit rejections; it is stricter than the upstream wire format. Structured/media requests and full SDK validation are untested. `model/mojev.AssembleAnswer` matches five synthetic upstream Choice/Noul/Score public-answer cases. `AssembleTextDecision` combines decoded text requests, the approved tokenizer and injected sorted logits, matching a three-question public response and 60 input tokens; neither API has an HTTP or model execution path. Native encoder mask execution, multimodal packing, end-to-end logits and vision input are unimplemented. `RuntimeReady=false`.

The [hybrid encoder contract](mojev-hybrid-encoder-contract.md) defines the visibility and state-ownership tests required before any Go encoder integration. It separates parity with the leaky released checkpoint from a repaired isolation path, which needs a new independent oracle and quality evaluation.

## Separate gates

1. Approval for the first checkpoint probe was granted. Its hash-pinned file was stored in `/dev/shm` (about 23 GB free before download), away from the repository; `/srv` had about 5.8 GB free. Check storage and memory again before running larger probes, and pin artifact hashes before loading them.
2. The bounded upstream CPU probe captured BF16 encoder hidden rows and F32 head logits for synthetic token IDs and an absent option. Resolve the cross-question leakage in the hybrid encoder before promising independent decisions; verify full- and linear-attention mask semantics against a fresh approved checkpoint oracle. Capture independent released-model fixtures for the multimodal processor, broader packed state/question/candidate spans and public Choice/Noul/Score probabilities. Include permuted candidates, hostile delimiters, missing options, mixed text/image inputs and rejection cases.
3. Decide whether to match the leaky release or validate repaired isolation, then implement a bounded native scorer with request-owned scratch against the corresponding independent oracle. Match logits and answers before profiling or claiming inference. Qualify peak/retained memory, concurrency, ARM64/RISC-V execution and service wiring separately.
4. Evaluate quality and calibration on a fresh held-out cohort. Do not reuse the frozen Jev bake-off or present published upstream metrics as local results.

MoJev's packed readout differs from Simple-JEV's selected next-token label logits and Kev's pointer head. Keep all three adapters separate.
